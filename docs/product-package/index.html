    How this was captured

    Every surface was rendered from the application itself against the canonical synthetic demo world — the same dataset the demo runs on — then photographed at a viewport sized to each page, so the fixed navigation rail spans the full height of every image rather than stopping partway down.

    No screen was mocked, retouched, or composed by hand. Where a room is sparse, it is sparse because the dataset has nothing in it yet, and that empty state is what the product shows.

    Two things to know before you review. The build carries one unreleased surface behind a feature flag that is switched off here, so these images show the product as the demo serves it today — not the in-progress work. And the sign-in screen is absent: this environment has no identity provider configured, so it renders a setup notice rather than the real form, and a misleading screenshot is worse than none.

    What this package does not cover

    • Dark mode — the product ships a full dark theme; it was out of scope for this pass.
    • Responsive breakpoints — every capture is 1440px wide. The layouts do reflow to phone width, and nothing scrolled sideways at any width tested.
    • Interaction states — hover, focus, loading, error and in-flight states are not shown, with one exception: the Sponsor ⇄ Partner disclosure toggle is captured in both states, because the difference between them is the product's central claim.
    • Sign-in and two detail rooms (a campaign, an import batch) — the dataset has no campaigns or import batches, so those routes have no record to render.
